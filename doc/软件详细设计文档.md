# J-Link 智能调试与分析上位机 - 详细软件设计文档 (SDD)

## 1. 项目概述与设计目标

本项目旨在基于 **C# (.NET 8.0 / WinForms)** 开发一款兼具**现代化高颜值界面**与**后台自动化 Skill 赋能能力**的 J-Link 综合调试上位机（以下简称 **JLink-Studio-Pro**）。

### 1.1 核心功能目标
1. **极速 RTT 终端**：支持多通道 RTT 数据的毫秒级采集、ANSI 颜色高亮、正则过滤及结构化日志解析。
2. **动态变量观测 (Live Watch)**：无需暂停 CPU（基于 HSI/Background Memory Access），通过解析 `.elf`/`.axf` 符号表，实时读写全局变量、结构体及数组，支持高频波形绘制。
3. **外设寄存器视图 (SVD Viewer)**：解析芯片厂商提供的 `.svd` 文件，树状展示外设寄存器及位域（Bit-fields）含义，支持在线修改与位操作。
4. **AI / Skill 自动化网关（核心亮点）**：内置轻量级后台服务（Local REST API / WebSocket / MCP 协议桥接），允许外部 AI Agent、Python 脚本或自动化测试 Skill **无感设置上位机参数、读取实时变量快照、抓取异常时的寄存器现场与 RTT 日志**，实现闭环的智能分析与故障诊断。
5. **高颜值现代化 UI**：彻底摒弃传统 WinForms 老旧风格，采用浅色现代风（Slate + Blue）与**“左侧固定导航栏 + 右侧动态子界面工作区”**的清爽布局架构。

## 4. 核心功能模块详细设计

### 4.1 J-Link 底层通信封装层 (`JLinkInterop`)

通过 C# `DllImport` 封装 `JLinkARM.dll`（64位系统使用 `JLink_x64.dll`）。

*   **DLL 定位策略（`JLinkLibraryLocator`）**：程序不要求把 DLL 复制到输出目录，而是通过 `NativeLibrary.SetDllImportResolver` 动态解析真实路径，按以下顺序探测：
    1. 手工配置目录（界面「偏好设置 → J-Link 驱动目录…」）
    2. 环境变量 `JLINK_STUDIO_DLL_DIR`
    3. **默认安装目录 `D:\Program Files\SEGGER\JLink_V948`**
    4. `%ProgramFiles%\SEGGER\JLink_V*` 中版本号最高的目录
    5. `%ProgramFiles(x86)%\SEGGER\JLink_V*` 中版本号最高的目录
    6. 程序运行目录（随程序分发的 DLL）
    7. 系统 `PATH`

    版本标签由目录名推导（如 `JLink_V948` → `V9.48`），界面与日志会同时展示版本与实际加载路径；解析失败时自动回落到模拟器模式。
*   **关键 API 映射**：
    *   **设备连接与配置**：`JLINKARM_OpenEx`, `JLINKARM_Close`, `JLINKARM_TIF_Select` (选择 SWD/JTAG), `JLINKARM_SetSpeed`, `JLINKARM_ExecCommand` (用于设置 Device 型号，如 `"device = STM32F407VG"` 或配置 RTT 控制块地址)。
    *   **内存无感读写（变量与寄存器基石）**：
        *   `JLINKARM_ReadMemEx(uint addr, uint numBytes, IntPtr pData, uint accessWidth)`
        *   `JLINKARM_WriteMemEx(uint addr, uint numBytes, IntPtr pData, uint accessWidth)`
    *   **RTT 专用接口**：
        *   `JLINK_RTTERMINAL_Control(uint cmd, IntPtr pConfig)` (启动、停止、查询通道缓冲区状态)。
        *   `JLINK_RTTERMINAL_Read(uint bufferIndex, byte[] pBuffer, uint bufferSize)`
        *   `JLINK_RTTERMINAL_Write(uint bufferIndex, byte[] pBuffer, uint bufferSize)`
*   **线程安全设计（极其重要）**：
    *   `JLinkARM.dll` 内部并非完全线程安全。必须设计一个 **单线程专属硬件访问队列 (`JLinkCommandQueue`)** 或使用高性能互斥锁（`SemaphoreSlim`），将 RTT 读取、变量轮询、寄存器读取及 Skill 下发的写操作统一排队执行，防止内存访问冲突导致 DLL 崩溃。

### 4.2 RTT 极速打印模块 (`RttService`)

1.  **控制块 (Control Block) 寻址**：
    *   支持三种模式：`Auto Detection`（全内存搜索 `_SEGGER_RTT`）、`Address`（直接从已加载的 `.elf` 符号表中自动提取 `_SEGGER_RTT` 符号地址，实现 **0延迟秒连**）、`Search Range`（指定 RAM 范围如 `0x20000000 0x10000`）。
2.  **高吞吐采集与 UI 防卡顿机制**：
    *   **后台采集线程**：以 1ms~5ms 周期调用 `JLINK_RTTERMINAL_Read`，将数据写入无锁环形缓冲区 `System.Threading.Channels.Channel<RttPacket>`。
    *   **双路分发**：
        *   **一路推向 Skill 网关与内存日志池**：无论当前右侧是否处于 RTT 子界面，后台始终保持接收与正则告警监控。
        *   **一路推向 `PageRttView` 子界面**：当该子界面处于激活可见状态（`Visible == true`）时，以 **30ms 定时批量合并刷新** 渲染至界面；当切到其他菜单子界面时暂停 UI 控件重绘，节省 CPU/GPU 资源。
3.  **结构化提取（为 Skill 赋能）**：
    *   内置正则提取器，例如当 RTT 打印 `[ADC] ch1=1204, ch2=3301` 时，可自动解析为 JSON 键值对存入时序缓存，供 Skill 直接拉取统计。

### 4.3 变量动态查看模块 (`VariableWatchService`)

1.  **ELF/DWARF 符号解析**：
    *   加载编译生成的 `.elf` 或 `.axf` 文件。
    *   解析 `.symtab` 段获取全局变量的基础地址与大小；进一步解析 `.debug_info` (DWARF 格式) 获取复合类型（`struct`, `union`, `enum`, 数组维度及指针类型）的树状展开结构。
2.  **符号数据模型 (`WatchSymbol`)**：
    ```csharp
    public class WatchSymbol
    {
        public string Name { get; set; }           // 如 "g_motorCtrl.pid.kp"
        public uint Address { get; set; }          // 0x200001A4
        public DataType Type { get; set; }         // UInt8, Int32, Float, Struct...
        public int ByteSize { get; set; }          // 4
        public object CurrentValue { get; set; }   // 实时解析值
        public double RefreshRateHz { get; set; }  // 采样率：1Hz ~ 1000Hz
        public bool PlotEnabled { get; set; }      // 是否投射到波形图
        public bool ExposeToSkill { get; set; }    // 是否暴露给后台 Skill 重点监控
        public List<WatchSymbol> Children { get; set; } // 结构体成员
    }
    ```
3.  **连续内存合并读取优化 (Memory Coalescing)**：
    *   当用户或 Skill 同时监控一个结构体中的多个字段，或地址相近的多个变量（间距小于 64 字节）时，调度器自动将其合并为单次 `JLINKARM_ReadMemEx` 块读取，随后在内存中按偏移量切片解析，大幅提升总线吞吐率。

### 4.4 硬件寄存器查看模块 (`RegisterViewService`)

1.  **SVD 模型构建**：
    *   解析 `.svd` XML 文件，生成 `SvdPeripheral` (如 `TIM1`, `USART1`, 基地址 `0x40010000`) -> `SvdRegister` (如 `CR1`, 偏移 `0x00`, 复位值, 读写权限) -> `SvdField` (如 `CEN`, Bit `[0:0]`, 枚举解释 `"0: Counter disabled, 1: Counter enabled"`).
2.  **按需读取机制（避免触发硬件副作用）**：
    *   很多 MCU 的状态寄存器（如串口 `DR` 数据寄存器）具有**“读清零 (Read-to-Clear)”**特性。
    *   **设计策略**：仅对用户在寄存器子界面中**当前选中并展开**的外设寄存器，或被 Skill 显式点名读取的寄存器发起 `ReadMemEx`（强制 32-bit 对齐访问），并在 SVD 中标记 `readAction="clear"` 的寄存器旁显示警告图标，默认不自动轮询。
3.  **位域可视化修改**：
    *   提供 32 位二进制勾选格与位域下拉框，修改某几个 Bit 后，支持一键生成 `Read-Modify-Write` 操作写入硬件。

### 5.3 左侧菜单栏与右侧五大子界面详细设计

左侧使用 `AntdUI.Menu` 控件（宽度默认 `210px`，支持点击顶部 `[≡]` 按钮折叠为 `64px` 纯图标模式，释放更大空间给右侧图表）。菜单项支持 **实时状态微标 (Badge)**（例如 RTT 有新报错时显示红点、Skill 正在调用时显示闪烁蓝点）。

右侧工作区 (`PanelPageHost`) 根据左侧菜单点击，动态切换以下 **5 个核心子界面 (`UserControl`)**：

#### 子界面 1：`PageDeviceConfig` (🔌 设备与工程配置)
*   **页面定位**：工程初始化大本营，采用清爽的**双列圆角卡片布局**。
*   **左卡片（J-Link 硬件连接配置）**：USB 序列号选择、目标芯片型号选择（带模糊搜索弹窗）、接口类型（SWD/JTAG）、通信时钟速率滑块（100kHz ~ 50MHz）、一键连接/复位/暂停按钮。
*   **右卡片（调试符号与文件挂载）**：
    *   `.elf` / `.axf` 固件路径选择（支持文件拖拽进入），开启**“编译后文件更新自动重载 (FileSystemWatcher)”**开关（方便 Keil/IAR 重新编译后上位机无感刷新变量地址）。
    *   `.svd` 寄存器描述文件路径选择。
    *   RTT 控制块寻址策略配置（自动从 ELF 提取 `_SEGGER_RTT` 地址 / 手动指定）。

#### 子界面 2：`PageRttView` (💻 RTT 极速终端)
*   **页面定位**：全屏沉浸式日志分析与命令交互终端。
*   **顶部工具条**：通道切换胶囊按钮 (`Ch0: Terminal`, `Ch1: Waveform`, `Ch2: Error`)、日志级别过滤标签 (`ALL` / `INFO` / `WARN` / `ERROR`)、正则表达式实时高亮搜索框、暂停滚屏开关、导出 `.log` 按钮、清空按钮。
*   **中部主显示区**：高性能虚拟双缓冲富文本框（支持 ANSI Escape Color 解析，绿/黄/红分色显示下位机日志，左侧固定显示上位机毫秒级时间戳 `[14:22:01.402]`）。
*   **底部发送栏**：支持 ASCII 字符串与 Hex 十六进制切换发送、历史指令上下键回溯、右侧附带 **“快捷指令宏按钮区”**（用户可自定义如 `[软复位]`、`[打印内存栈]`、`[校准零点]` 等一键下发按钮）。

#### 子界面 3：`PageWatchView` (👀 变量监控与波形)
*   **页面定位**：动态变量读写与高速示波器二合一视图，内部采用 `SplitContainer`（支持**左右分屏**或**上下分屏**一键切换）。
*   **第一分屏（ELF 符号搜索弹窗 + LiveWatch 树形表格）**：
    *   支持模糊搜索 `.elf` 中的所有全局变量并加入监控表。
    *   表格列：`[波形勾选]`、`[Skill暴露]`、`变量名称 (支持结构体展开)`、`绝对地址`、`数据类型`、`当前物理值 (支持双击直接在线改写)`、`进制格式切换 (Dec/Hex/Bin/Float)`、`刷新率`。
*   **第二分屏（ScottPlot 实时示波器）**：
    *   凡是在表格中勾选了 `[波形]` 的变量，实时绘制多通道高帧率曲线，支持鼠标滚轮缩放 X/Y 轴、游标测量（Crosshair）、一键暂停抓图及导出 CSV 数据。

#### 子界面 4：`PageSvdView` (⚙️ 硬件寄存器视图)
*   **页面定位**：芯片外设寄存器与位域级精细调试面板，采用**左-中-右三栏联动结构**。
*   **左栏（外设分类树）**：按 `GPIOA`, `TIM1`, `USART1`, `ADC1`, `SCB` 等外设分组列表，带快速过滤框。
*   **中栏（寄存器列表）**：展示选中外设下的所有寄存器（名称、偏移地址、当前 32位 Hex 值、复位值、描述），值变化时琥珀黄高亮。
*   **右栏（32-Bit 位域可视化交互面板）**：
    *   顶部展示一个直观的 **32格二进制位图 (`Bit 31` ~ `Bit 0`)**，点击任意格子可直接翻转该 Bit（`0` 变 `1`）。
    *   下方列出 SVD 解析出的具体位域（例如 `TIM1->CR1` 的 `CMS[6:5]: 中心对齐模式选择`），直接提供包含 SVD 枚举注释的下拉框，选择后点击 `[写入寄存器]` 即可完成安全的掩码位写入。

#### 子界面 5：`PageSkillGateway` (🤖 Skill 网关中心)
*   **页面定位**：专为后台 AI Agent / 自动化分析 Skill 打造的可视化管控与审计中心。
*   **顶部状态卡片**：显示内嵌 REST API / WebSocket / MCP 服务运行状态、监听端口设置（默认 `5080`）、一键复制 `OpenAPI Swagger URL` 或导出 `MCP JSON 配置` 按钮。
*   **中部左区（暴露给 Skill 的数据白名单）**：集中展示当前允许外部 Skill 读取或修改的变量列表、寄存器范围及安全写保护开关（例如限制 `g_motorPid.kp` 允许 Skill 写入的范围为 `0.0 ~ 10.0`，防止 AI 算错参数烧毁硬件）。
*   **中部右区（Skill 实时交互审计流 & 诊断报告面板）**：
    *   实时滚动展示外部 Skill 发起的每一次 API 请求（如 `[14:25:10] AI-Skill 调用 POST /variables/write 修改 kp = 1.45, 耗时 2ms`）。
    *   当外部 Skill 完成数据分析并通过接口回传诊断结论时，在此处以 Markdown 富文本卡片形式直接渲染展示分析结果。

## 6. 后台参数配置与 Skill 分析接口设计（核心亮点）

为了让外部的 **AI Agent (如 Claude Code / Cursor / Dify / 自研分析 Skill)** 或 **Python 自动化分析脚本** 能够无缝控制上位机并获取数据进行闭环调优，系统在后台内置了一个独立于 UI 子界面的双模通信网关（`SkillGatewayService`）。

### 6.1 通信架构模式
1.  **嵌入式 RESTful API (`http://127.0.0.1:5080/api/v1/...`)**：用于配置上下位机参数、按需读写变量/寄存器、拉取历史统计数据。自带 `/swagger` 页面，可直接导出 OpenAPI JSON 规范注册为 AI 的 Tool / Skill。
2.  **WebSocket 实时流 (`ws://127.0.0.1:5080/ws/stream`)**：用于向 Skill 高频推送 RTT 日志流、高频变量采样流（如 1kHz 的电机电流数据）以及硬件异常告警事件。

### 6.2 核心 API 接口清单（供 Skill 调用）

#### (1) 系统与连接控制接口
*   `POST /api/v1/session/config`
    *   **功能**：Skill 动态配置上位机参数并连接硬件（同步更新 `PageDeviceConfig` 子界面显示）。
    *   **请求体**：
        ```json
        {
          "device": "STM32F407VG",
          "interface": "SWD",
          "speedKhz": 4000,
          "elfPath": "D:/firmware/build/app.elf",
          "svdPath": "D:/firmware/svd/STM32F407.svd",
          "rttSearchMode": "AutoFromElf",
          "autoConnect": true
        }
        ```

#### (2) 变量读写与批量采样接口（支持符号名直接操作）
*   `POST /api/v1/variables/read`
    *   **功能**：通过变量名列表直接读取当前物理值（上位机自动查 ELF 符号表转换地址并拼包读取）。
    *   **请求体**：`{ "names": ["g_motorPid.kp", "g_motorPid.error", "g_adcBuffer[0]"] }`
    *   **响应体**：
        ```json
        {
          "timestamp": 1777382400123,
          "data": {
            "g_motorPid.kp": { "address": "0x20000100", "type": "float", "value": 1.25 },
            "g_motorPid.error": { "address": "0x2000010C", "type": "float", "value": -0.04 },
            "g_adcBuffer[0]": { "address": "0x20000400", "type": "uint16", "value": 2048 }
          }
        }
        ```
*   `POST /api/v1/variables/write`
    *   **功能**：Skill 分析完数据后，反向动态修改下位机参数（如修改控制参数、注入故障测试点）。
    *   **请求体**：
        ```json
        {
          "writes": [
            { "name": "g_motorPid.kp", "value": 1.65 },
            { "name": "g_motorPid.ki", "value": 0.05 }
          ]
        }
        ```
*   `POST /api/v1/variables/capture-timeseries`
    *   **功能**：**专为分析 Skill 设计的同步块采集接口**。让上位机以指定频率连续采集某几个变量 $N$ 毫秒，计算完统计特征（最大值、最小值、均值、标准差、超调量）及原始数组后一次性返回给 Skill，避免 AI 频繁请求。
    *   **请求体**：
        ```json
        {
          "names": ["g_motor.targetSpd", "g_motor.actualSpd"],
          "sampleRateHz": 500,
          "durationMs": 2000
        }
        ```

#### (3) 硬件寄存器与故障诊断接口
*   `GET /api/v1/registers/peripheral/{peripheralName}`
    *   **功能**：读取如 `USART1` 或 `SCB`（系统控制块）下所有寄存器的当前值及 SVD 解析出的位域语义。
    *   **典型 Skill 场景**：当目标板卡死时，Skill 调用 `/api/v1/registers/peripheral/SCB` 读取 `CFSR`、`HFSR`、`MMFAR`、`BFAR` 寄存器，上位机自动按 SVD 拆解出具体哪一位报错（如 `PRECISERR = 1: 精确数据总线错误`），连同 CPU 核心寄存器 `R0-R15, PC, LR` 一起打包返回，AI 即可瞬间给出 HardFault 根因分析报告！
*   `POST /api/v1/registers/write-field`
    *   **功能**：按外设名+寄存器名+位域名进行安全修改。
    *   **请求体**：`{ "peripheral": "TIM1", "register": "CR1", "field": "CEN", "value": 1 }`

#### (4) RTT 日志查询与交互接口
*   `GET /api/v1/rtt/logs?channel=0&lastLines=200&regexFilter=ERROR|WARN`
    *   **功能**：Skill 获取最近 $N$ 条 RTT 打印日志，支持正则过滤，用于上下文诊断。
*   `POST /api/v1/rtt/send`
    *   **功能**：Skill 向目标板发送 RTT 命令（如触发板端 Shell 命令 `"reboot"` 或 `"cali_sensor"`）。

### 8.1 主窗体左菜单 + 右子界面无缝切换路由器 (`MainForm.cs` & `PageRouter.cs`)

为了确保切换左侧菜单时**右侧子界面瞬间响应、不闪烁、不丢失滚动条位置与波形状态**，采用单例缓存容器 + `ISubPageView` 生命周期接口设计：

```csharp
using System;
using System.Collections.Generic;
using System.Windows.Forms;

namespace JLinkStudio.WinFormsUI.Navigation
{
    // 子界面统一生命周期接口
    public interface ISubPageView
    {
        void OnPageActivated(); // 当左侧菜单切到当前子页面时触发（恢复UI高频刷新定时器）
        void OnPageHidden();    // 当切走隐藏时触发（暂停UI控件重绘，但后台采集继续）
    }

    // 右侧子页面路由管理器
    public class PageRouter
    {
        private readonly Control _hostContainer;
        private readonly Dictionary<string, UserControl> _pageCache = new();
        private UserControl? _currentPage;

        public PageRouter(Control hostContainer)
        {
            _hostContainer = hostContainer;
        }

        public void RegisterPage(string key, UserControl pageInstance)
        {
            pageInstance.Dock = DockStyle.Fill;
            pageInstance.Visible = false;
            _pageCache[key] = pageInstance;
            _hostContainer.Controls.Add(pageInstance);
        }

        public void NavigateTo(string key)
        {
            if (!_pageCache.TryGetValue(key, out var targetPage)) return;
            if (_currentPage == targetPage) return;

            _hostContainer.SuspendLayout();
            try
            {
                // 1. 通知旧子页面暂停 UI 渲染
                if (_currentPage is ISubPageView oldView)
                    oldView.OnPageHidden();
                if (_currentPage != null)
                    _currentPage.Visible = false;

                // 2. 激活并显示新子页面
                targetPage.Visible = true;
                targetPage.BringToFront();
                _currentPage = targetPage;

                if (targetPage is ISubPageView newView)
                    newView.OnPageActivated();
            }
            finally
            {
                _hostContainer.ResumeLayout(true);
            }
        }
    }
}
```

在 `MainForm.cs` 中绑定左侧 `AntdUI.Menu` 选择事件：

### 8.2 J-Link P/Invoke 线程安全访问骨架 (`JLinkWrapper.cs`)

```csharp
using System;
using System.Runtime.InteropServices;
using System.Threading;

namespace JLinkStudio.Core.Interop
{
    public class JLinkWrapper : IDisposable
    {
        private const string DllName = "JLink_x64.dll";
        private readonly SemaphoreSlim _busLock = new SemaphoreSlim(1, 1);

        [DllImport(DllName, CallingConvention = CallingConvention.StdCall, CharSet = CharSet.Ansi)]
        private static extern IntPtr JLINKARM_OpenEx(IntPtr pfLog, IntPtr pfErrorOut);

        [DllImport(DllName, CallingConvention = CallingConvention.StdCall)]
        private static extern void JLINKARM_Close();

        [DllImport(DllName, CallingConvention = CallingConvention.StdCall, CharSet = CharSet.Ansi)]
        private static extern int JLINKARM_ExecCommand(string cmd, IntPtr pError, int bufferSize);

        [DllImport(DllName, CallingConvention = CallingConvention.StdCall)]
        private static extern int JLINKARM_ReadMemEx(uint addr, uint numBytes, byte[] pData, uint accessWidth);

        [DllImport(DllName, CallingConvention = CallingConvention.StdCall)]
        private static extern int JLINKARM_WriteMemEx(uint addr, uint numBytes, byte[] pData, uint accessWidth);

        [DllImport(DllName, CallingConvention = CallingConvention.StdCall)]
        private static extern int JLINK_RTTERMINAL_Read(uint bufferIndex, byte[] pBuffer, uint bufferSize);

        public bool ReadMemorySafe(uint address, byte[] buffer, uint accessWidth = 0)
        {
            _busLock.Wait();
            try
            {
                int res = JLINKARM_ReadMemEx(address, (uint)buffer.Length, buffer, accessWidth);
                return res >= 0;
            }
            finally
            {
                _busLock.Release();
            }
        }

        public bool WriteMemorySafe(uint address, byte[] buffer, uint accessWidth = 0)
        {
            _busLock.Wait();
            try
            {
                int res = JLINKARM_WriteMemEx(address, (uint)buffer.Length, buffer, accessWidth);
                return res >= 0;
            }
            finally
            {
                _busLock.Release();
            }
        }

        public int ReadRttSafe(uint channel, byte[] buffer)
        {
            _busLock.Wait();
            try
            {
                return JLINK_RTTERMINAL_Read(channel, buffer, (uint)buffer.Length);
            }
            finally
            {
                _busLock.Release();
            }
        }

        public void Dispose() => JLINKARM_Close();
    }
}
```

### 8.3 WinForms 内部自宿主 Skill API 服务启动器 (`EmbeddedHostService.cs`)

在 WinForms 启动时（`Program.cs` 或 `MainForm_Load`），在后台开启 Kestrel 服务，将核心引擎的单例直接注入到 API 控制器中，实现**零内存拷贝**的极速后台操控：

```csharp
using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Hosting;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using System.Threading.Tasks;

namespace JLinkStudio.SkillGateway
{
    public class EmbeddedHostService
    {
        private IHost? _webHost;

        public async Task StartSkillServerAsync(
            int port, 
            VariablePollEngine varEngine, 
            RegisterAccessService regService, 
            RttEngine rttEngine)
        {
            var builder = WebApplication.CreateBuilder();
            
            // 配置监听本地端口
            builder.WebHost.UseKestrel(options => options.ListenLocalhost(port));

            // 将上位机核心引擎的单例注入到 DI 容器，供 API Controller 直接调用
            builder.Services.AddSingleton(varEngine);
            builder.Services.AddSingleton(regService);
            builder.Services.AddSingleton(rttEngine);

            builder.Services.AddControllers();
            builder.Services.AddEndpointsApiExplorer();
            builder.Services.AddSwaggerGen(); // 自动生成 OpenAPI 供 Skill 发现

            var app = builder.Build();
            app.UseSwagger();
            app.UseSwaggerUI();
            app.UseWebSockets();
            app.MapControllers();

            _webHost = app;
            await _webHost.StartAsync();
        }

        public async Task StopSkillServerAsync()
        {
            if (_webHost != null) await _webHost.StopAsync();
        }
    }
}
```

## 9. 典型 Skill 协同工作流演练（应用场景展示）

### 场景一：AI Skill 自动整定电机 PID 参数
1.  **配置准备**：用户在左侧菜单【🔌 设备与工程配置】加载 `.elf` 文件，或者由 AI Skill 直接调用 `POST /api/v1/session/config` 自动挂载 `.elf` 并连接 J-Link。
2.  **下发激励与采样**：用户切换到左侧菜单【👀 变量监控与波形】观察画面；AI Skill 在后台调用 `POST /api/v1/variables/write` 将目标转速 `g_targetSpeed` 从 `0` 设为 `1000`，同时调用 `POST /api/v1/variables/capture-timeseries` 录制 `g_actualSpeed` 在 1.5 秒内的 500Hz 响应曲线。
3.  **Skill 分析与迭代**：上位机将采集到的时序数据及计算好的超调量（Overshoot = 28%）、稳态误差（SteadyError = 2.1）返回给 Skill。AI 判断超调过大，自动计算出新的 `Kp` 与 `Kd`，再次调用 `/api/v1/variables/write` 在线写入 MCU RAM，同时右侧子界面上的 `LiveWatch` 表格高亮闪烁提示 AI 刚刚修改了参数，ScottPlot 曲线实时展示出第二次阶跃响应已变得平滑完美。

### 场景二：嵌入式异常 / 死机现场一键智能诊断
1.  **触发监控**：上位机后台的 `RttEngine` 监控到 RTT 打印出 `"HardFault_Handler"` 关键字（此时左侧菜单【💻 RTT 极速终端】自动亮起红色告警角标）。
2.  **现场抓取**：自动触发 Skill 分析流程，Skill 调用 `/api/v1/registers/peripheral/SCB` 及外设寄存器接口，结合 SVD 位域描述读取故障寄存器，并拉取最后 100 行 RTT 日志。
3.  **诊断输出**：Skill 结合 ELF 符号表中的函数地址范围，直接定位出是哪个 C 函数出现了空指针解引用或数组越界，并将诊断结论推送到左侧菜单【🤖 Skill 网关中心】子界面的诊断卡片中。
